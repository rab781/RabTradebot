# REST API Reference

The Trading Bot Dashboard provides a REST API for real-time market data, portfolio tracking, and system health monitoring.

## Authentication

By default, the REST API runs without authentication. It is designed to be accessed from a secure local network or a protected frontend.

## Rate Limiting

Requests to the `/api` routes are limited to **100 requests per minute per IP**. If you exceed this limit, the API returns a `429 Too Many Requests` status code with the following JSON payload:

```json
{
  "error": "Too many requests, please try again later."
}
```

## Pagination

Endpoints that return lists (such as trades, signals, and news) support pagination via the `limit` query parameter.
- Trades default limit: 50
- Signals and News default limit: 20

## Error Handling

When an internal error occurs (e.g., state manager failure or database error), the API returns a `500 Internal Server Error` status code with the following JSON response:

```json
{
  "error": "An internal server error occurred"
}
```

## Endpoints

### Get Dashboard Data
Retrieves the high-level summary of the bot's state, including overall profit, active signals, and system status.

**GET** `/api/dashboard`

**Responses:**
- `200 OK`: Returns the dashboard summary object.
- `500 Internal Server Error`: `{"error": "An internal server error occurred"}`
- `429 Too Many Requests`: `{"error": "Too many requests, please try again later."}`

---

### Get Trades
Fetches historical trades executed by the bot. You can use this to analyze past performance.

**GET** `/api/trades`

**Parameters:**
- `limit` (optional, integer): Number of trades to return. Defaults to 50.

**Responses:**
- `200 OK`: Returns an array of trade objects.
- `500 Internal Server Error`: `{"error": "An internal server error occurred"}`
- `429 Too Many Requests`: `{"error": "Too many requests, please try again later."}`

---

### Health Check (Internal)
Basic health check for internal monitoring. Note that this endpoint is under the `/api` rate limiter.

**GET** `/api/health`

**Responses:**
- `200 OK`: Returns `{"status": "OK", "timestamp": "...", "uptime": 123}`.
- `429 Too Many Requests`: `{"error": "Too many requests, please try again later."}`

---

### Health Check (External Monitoring)
Comprehensive health monitoring endpoint that aggregates system status, memory usage, and component health. This endpoint is *not* rate limited (it is outside the `/api` prefix).

**GET** `/health`

**Responses:**
- `200 OK`: System is healthy. Returns a detailed payload with status, memory usage, and component checks.
- `503 Service Unavailable`: One or more critical components are down. Returns the same detailed payload indicating the failure.
