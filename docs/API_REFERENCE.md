# Trading Bot Dashboard API Reference

The Trading Bot Dashboard API provides endpoints to retrieve real-time state, trades, signals, news, and system health metrics. It is designed to power the web dashboard and allow external monitoring integrations.

## Authentication
By default, the API **runs without authentication**. It is designed to be run locally or behind a secure reverse proxy on a trusted network. Do not expose this API directly to the public internet without adding an authentication layer at your proxy.

## Rate Limiting
Requests are limited to **100 requests per minute per IP address**.

If you exceed this limit, the API will respond with:
- **HTTP Status**: `429 Too Many Requests`
- **Response**: `{"error": "Too many requests, please try again later."}`

## Pagination
Endpoints that return collections (e.g., `/api/trades`, `/api/signals`, `/api/news`) support a `limit` query parameter to control the number of items returned.

**Example:**
`GET /api/trades?limit=10`

## Error Handling
In the event of an internal error, the API will catch the exception and respond with:
- **HTTP Status**: `500 Internal Server Error`
- **Response**: `{"error": "An internal server error occurred"}`

The underlying error details are logged internally by the bot's logging system.

## Endpoints

### Get Dashboard Data
Retrieves the aggregated dashboard state, including recent trades, active signals, news, portfolio status, and basic bot stats.

**Request:**
`GET /api/dashboard`

**Response (200 OK):**
Returns a JSON object containing the complete dashboard state from the `BotStateManager`.

---

### Get Trades
Retrieves a list of recent trades executed by the bot.

**Request:**
`GET /api/trades`

**Parameters:**
- `limit` (optional): `number` - Number of trades to return (Default: 50).

**Response (200 OK):**
Returns a JSON array of trade objects.

---

### Get Open Trades
Retrieves a list of currently open trading positions.

**Request:**
`GET /api/trades/open`

**Response (200 OK):**
Returns a JSON array of open trade objects.

---

### Get Signals
Retrieves recent trading signals generated by the bot's analysis engine.

**Request:**
`GET /api/signals`

**Parameters:**
- `limit` (optional): `number` - Number of signals to return (Default: 20).

**Response (200 OK):**
Returns a JSON array of signal objects.

---

### Get News
Retrieves recent AI-analyzed news items affecting the crypto markets.

**Request:**
`GET /api/news`

**Parameters:**
- `limit` (optional): `number` - Number of news items to return (Default: 20).

**Response (200 OK):**
Returns a JSON array of news objects.

---

### Get Portfolio
Retrieves the current portfolio balance and asset allocation.

**Request:**
`GET /api/portfolio`

**Response (200 OK):**
Returns a JSON object representing the portfolio state.

---

### Get Bot Stats
Retrieves operational statistics for the bot.

**Request:**
`GET /api/stats`

**Response (200 OK):**
Returns a JSON object containing stats such as command counts and operational metrics.

---

### Basic Health Check
Provides a simple health check to verify the API web server is running.

**Request:**
`GET /api/health`

**Response (200 OK):**
```json
{
  "status": "OK",
  "timestamp": "2023-10-27T10:00:00.000Z",
  "uptime": 3600
}
```

---

### External Monitoring Health Check
Provides a comprehensive system health snapshot, aggregating status from all internal components (database, APIs, models) via the `healthMonitor`.

**Request:**
`GET /health`

**Response (200 OK / 503 Service Unavailable):**
Returns HTTP 200 if the overall status is healthy or degraded. Returns HTTP 503 if the overall status is 'down'.

```json
{
  "status": "operational",
  "timestamp": "2023-10-27T10:00:00.000Z",
  "uptime": 3600,
  "memoryUsageMb": 150,
  "requestCount": 1050,
  "components": {
    "binance_api": { "status": "operational", "latencyMs": 45 },
    "database": { "status": "operational", "latencyMs": 5 }
  }
}
```
